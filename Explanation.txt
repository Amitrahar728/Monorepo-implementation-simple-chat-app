then what happens:
it comes to package.json in the directory and see this line there "build": "turbo run build",
which runs when we do npx run build in terminal 
then as it defines turbo run build so we direct to turbo.json file now :

where there are 3 lines in build part others parts are easily understandable :

"build": {
      "dependsOn": ["^build"],  
      "inputs": ["$TURBO_DEFAULT$", ".env*"],
      "outputs": [".next/**", "!.next/cache/**"]
},


dependson : tells us about the dependency graph what needs to be developed before the other thing we build like ui components need to be build before apps folder as they are required
means turborepo maintains a Directed acyclic graph of dependecies in the project over each other and build them in the topological order .

inputs :
what are the inputs this says what are the inputs do i have to build it from scratch or pick it from cache
if anything changes in both turbo_defaults(contains almost all are folder files if we expand it it contain "./app/* , ./packages/*) like these  and .env file we need to build it again otherwise pick directly from .next folder the cache 

one more thing
 in a node.js project if .env is changed then re build it again is neccessary 
 but not in a next.js project it is not required to build it again everytime so we can remove it from inputs
 

Why so ??




outputs:
first time when we build the .next folder is generated and saved in remote cloud place and whenever we again do 
build it picks it from remote cache which led to efficient build 
and second part says dont cache anything inside next/cache folder leave it .
